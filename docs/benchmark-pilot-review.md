# Benchmark 真实模型 Pilot 准备审查

审查日期：2026-11-02。审查对象为 `codex/lightweight-benchmark`，原基础设施提交为
`939d2b96fa288ec1d94292e6afa70372b672e2e2`。本轮只修改 Benchmark 包、相关测试和文档，
不运行真实模型、不运行72次实验，也不为测试网站修改 Agent 或 Executor。

## 结论与运行条件

代码与离线验证已具备四次真实 Pilot 的执行条件；当前环境具备 browser-use 0.13.11、
Playwright 1.64.0、Chromium 文件以及模型凭据，且 AutoScraper 导入自当前仓库。
**本次没有验证供应商鉴权、模型可用性或实时网站连通性，尚未产生任何真实 Pilot 成绩。**

正式运行前仍需维护者完成下表人工确认，并在记录中写明审阅者、时间和结论；现有真值
仍如实标记为 source-reviewed，不伪造 human-reviewed。随后提交/固定代码 Commit，
确认工作区干净、模型和预算符合预期，再显式开启付费运行。预检失败会阻塞同任务所有组。

## 发现的问题与修复

| 问题 | 修复及影响 |
|---|---|
| 重放以 score.json.task_success 为条件 | 改为只检查退出码、完整执行和规则文件存在。独立真值不再决定后续运行，避免筛选语义正确规则后才计算复用成功率。 |
| CLI stdout 先存在内存，超时时丢失 | 使用实时转发的捕获器，保留已输出的 stdout/stderr；正常失败也解析 stderr 中的结构化反馈。 |
| 浏览器启动异常没有 execution.json | Worker 补齐失败状态、错误类型及经凭据清理的消息，不重试、不修复 Agent。 |
| Ctrl+C 可能遗留独立子进程 | 中断时终止整个进程组，保存退出状态，停止后续任务，CLI 返回130。 |
| Usage 对象存在被当成所有 Token 字段完整 | 读取既有事件并关联 call_id，逐字段统计覆盖；部分 completion/cache 缺失不再被当成完整成本。损坏/重复事件不能产生完整 Token 对照。 |
| 事件下界混入完整成本合计 | 完整成本与下界分列；缺失 Usage 仍为未知，不补零。Executor 的零模型成本由执行方式明确，不依赖日志是否完整。 |
| 中断或缺配对时仍给出提升数值 | 未完成或不平衡批次只展示原始成绩与覆盖数，不生成 Repair 提升。 |
| CSV 缺少退出码和失败摘要 | 增加退出码、超时、中断、业务状态、精确率/召回率、修复未启动原因与 failure_reasons。正确数据伴随失败退出仍不算任务成功。 |
| 预算范围大于生产 ValidationSettings | 对齐1000记录、20列表页、1000详情页上限，避免模型运行前后的配置错误。 |
| 实验协议仅是标签 | 校验命名组、Repair 开关、预留量和请求额度关系；非 Repair 预算必须一致，不能用相同标签掩盖不同条件。 |
| 证据损坏导致预检直接异常退出 | 保存 check.json 失败原因，不发起源访问或模型请求；同任务所有组统一阻塞。 |
| 车辆任务格式示例恰含首条真值 | 仅删除任务文字中的真实年份/库存例值，保留整段文本要求；六份标准答案及原始证据完全未改动。 |

严格评分公式没有放宽：必须正常完整执行、确切记录集、无重复、顺序一致、全部目标字段
正确。布尔值与数字、相对与绝对 URL、缺失与显式空值仍严格区分；记录顺序错误可以有
较高字段准确率，但严格任务成功必为 false。extra 非目标字段不参与比较。

任务成功率与字段/记录准确率衡量最终交付数据。生产 CLI 未发布数据时准确率为0，不
推测内部试抓取质量，也不把内部验证结果当作独立真值反馈给 Repair。

## Ground Truth 与原始证据

新增的 `benchmarks.evidence` 使用标准库 HTMLParser 重解析已提交证据，**不调用在线
oracle、不调用 AutoScraper、不读取 Agent 输出**。同时校验文件 SHA-256。六任务107条
记录、380个目标字段与原始证据全部一致。此检查证明源证据一致性，不能代替真人确认
任务定义或证明今天的网站仍然未变。

| 任务 | 证据核验 | 维护者需要确认的口径 |
|---|---|---|
| books-list | 两个列表快照的前25条；完整标题、价格、绝对链接一致 | 按默认目录顺序，标题取完整 title 属性，不以界面截断文字评分；价格保留英镑符号。 |
| books-detail | 首个列表前5条及其5份详情段落一致 | 描述取产品描述段落全文，保留网站原有重复、法语字符和 ...more，不作编辑。 |
| quotes-delayed | 三页快照各10条，取前25条一致 | 保留页面弯引号、标点与作者字符；标签按页面顺序比较，不能拼成单个字符串。 |
| cars-load-more | 累计30辆的快照取前25辆一致 | year 保留 Year: 标签；status 保留 Available 库存数量；包含所有出售状态，不作仅在售筛选。数据为虚构测试内容，不检查历史真实性。 |
| quotes-scroll | 最后累计30条快照取前25条一致，与延迟版序列相同 | 三份累计快照不能相加造成重复；默认顺序与前25条边界需认可。与延迟任务相关，不能视为独立数据集。 |
| local-network | 两份源 JSON 的两条记录与字面数据一致 | id/stock/price 为数值，active 为布尔；负数、0、false 必须保留。 |

人工确认应针对原始证据与任务口径，而非根据运行结果“修正答案”。如页面发生变化，应
显式版本化证据、任务与答案，禁止挑选有利于某组的答案版本。所有运行会保存自己的任务、
真值副本和哈希，历史成绩无需依赖最新仓库内容即可评分。

```bash
uv run python -m benchmarks audit --output output/benchmark-audit.json
```

源预检还会先离线验证冻结答案确实匹配原始证据，再采集实时源数据核对。两类失败均保留
原因并阻塞同任务的全部组，不能只保留成功的组。

## 数据泄漏与核心边界

Agent 只收到任务原文、URL、字段名、数量和一致的预算要求；不传标准记录、证据 DOM、
oracle 选择器、候选答案或已有 Spec。Pilot 两组均从零生成，非交互，不自动响应澄清。
Worker 虽为离线评分保存真值副本，但不读取它来构造 Agent 输入。

当前生产 build_tools 仅保留 navigate/done/click/scroll 再注册专用探索工具，已排除
原生读写文件和任意代码执行工具；没有给 Agent 提供可读取答案的文件清单。四组 CLI
参数测试确认 spec_input=None，输入参数不包含 truth.json/candidate.json。
这不是操作系统级的敌对 Agent 沙箱：仓库真值仍在本机文件系统，未来如增加文件、任意
代码或本地文件导航能力，需要重新审查隔离。公开经典测试数据也可能已存在于模型训练
数据中，因此不能据此证明面对未见网站的泛化能力。

相对基线 `e9b14c1`，原 Benchmark 提交 `939d2b9` 没有修改 src 下任何文件，本轮同样
没有修改 src。若与较旧的本地 main `991a21d` 比较，会看到两个已经存在的核心提交：

| 已有提交 | 内容 | 本轮处理 |
|---|---|---|
| 81b19f4 | 将访问前置条件归入协议并移除旧 login 参数，涉及执行器、Spec、CLI/UI | 保持不动，作为基线行为。 |
| e9b14c1 | 修复语义等待误处理访问验证、提交时遗漏人工访问要求 | 保持不动，不将其效果算作 Benchmark 改进。 |

本报告中的 main 是本地审查快照，不声称其等于当前 GitHub main。后续若变更实际产品
Commit，应另立实验版本；不能将基线修复前后的差异误称为 Repair 对照效果。

## 四次真实 Pilot 配置

文件：`benchmarks/configs/pilot.json`。只使用 equal-total 协议，不混入另外一套
equal-initial 实验。运行顺序如下：

| 顺序 | 任务 | Repair | 主请求上限 | 预留 | 最大 Repair |
|---:|---|---|---:|---:|---:|
| 1 | books-list | Off | 24 | 0 | 0 |
| 2 | books-list | On | 24 | 0 | 2 |
| 3 | cars-load-more | On | 24 | 0 | 2 |
| 4 | cars-load-more | Off | 24 | 0 | 0 |

统一模型 deepseek-flash、每轮12 Step、独立等待最多8请求、单请求输出上限3000 Token、
工作流240秒、外层600秒、每任务每组一次、无重放。模型名沿用仓库配置，不声称本轮已
向供应商核实其可用性。四次最多96个主请求加32个等待请求；这不是美元费用硬上限，
也不是会实际花完的请求数。单请求输出上限不限制输入 Token 总量。

关闭 Repair 默认会取消预留；本 Pilot 两组都明确设置预留0，避免首轮24对18的混杂。
Repair On 仍受同一请求/时间硬上限约束，可能因没有可恢复反馈或剩余不足3请求而从未
启动修复；须查看 repair_not_started_reason，不能把“未修复”推断为“修复无效”。
等待请求纳入总成本，不以 Step 代替请求。组序交换只减少顺序偏差，不能消除网络时间
波动、供应商缓存或模型随机性。四次运行只能确认端到端可用性和发现失败模式，不支持
统计显著性、因果提升或简历效果结论。

后续真实运行命令（**本轮未执行**）：

```bash
uv run --extra agent python -m benchmarks run \
  --config benchmarks/configs/pilot.json \
  --commit "$(git rev-parse HEAD)" --allow-llm
```

只使用干净的固定 Commit，不使用 --allow-dirty。运行期间不编辑代码、配置或答案。
需要手动取消时使用 Ctrl+C，当前单元保留中断结果，其余保持 pending，不自动补跑。

结果的独立重评分：

```bash
uv run python -m benchmarks score output/benchmark/<批次目录>
```

score.json 与 summary.json/csv 保存任务成功、记录/字段准确率、Precision/Recall、
LLM 来源及总请求数、Token、Usage 覆盖、墙钟/阶段耗时、真实修复次数、退出码、超时、
中断、业务状态、修复未启动原因和结构化失败原因。汇总中的完整成本与事件下界分开；
原始进程消息仍受既有凭据清理和文本长度限制，详细上下文优先查看既有 Trace。

## 离线验收与剩余风险

离线测试覆盖全部源证据一致性、严格评分/失败状态、局部 Usage 缺失、损坏计量、
不平衡批次、预算协议约束、实时输出、Ctrl+C 清理、无真值筛选的重放，以及通过脚本化
模型响应模拟完整四单元 Runner/Trace/评分导出。模拟只存在于测试临时目录，不能作为
真实 Pilot 数据。相关测试86项与原 tracing 回归46项，共132项通过；Ruff、格式检查及
git diff --check 通过，未运行真实模型或新浏览器抓取实验。独立源核验报告保存于
`output/benchmark-pilot-source-audit.json`。

仍需保留的风险：人工口径审阅未完成；实时网页可能漂移；供应商鉴权、Usage 返回与
模型连通性未实测；模型名后端可能更新且无可固定 seed；两任务相关性/小样本限制；本轮
仅验证 Linux 下取消清理，Windows 不保证清理所有浏览器后代。若任一条件不满足，应先
解决或按失败记录，禁止暗中更换任务、答案、预算或重跑至成功后挑选结果。
