## 本轮真实模型对照

两种提示词均在 PR 的同一套功能/验证代码上运行，只替换 `build_task`；
下表各次运行使用独立浏览器和进程，不添加用户提示、参考规则或字段预填。
均使用上述原始任务和模型，temperature=0，12 Step / 轮、24 次主模型请求、
6 次修复预留，其他配置沿用 UI 默认值，执行完整工作流与独立抓取。
另在临时 checkout 运行完整 main 作为环境参照。

没有用户澄清。该样本只说明模型转向了另一条路径，不能用来宣称网络选择已修复。
本轮没有借机调整来源语义检查或整个探索流程。

## 结论与验证边界

仅恢复原探索提示词没有在本轮验证中解决漏查网络；原 PR 和完整 main 的结果也存在
波动。样本量小且部分运行受连接故障干扰，不能据此估计稳定成功率，也不能断言
新增提示词是唯一根因或工具 Schema 已被证明是根因。

后续若继续定位，应在固定的 DOM 失败检查点上，分别隔离任务说明与模型可见工具
Schema/描述，比较下一步选择；需要保留所有失败、提问和来源切换样本。本轮未引入
强制网络检查、额外提醒、动态工具路由或新的探索控制流。

恢复提示词后的现有 Agent / 网络功能回归：79 passed、1 skipped；Ruff 与差异检查通过。
这些确定性测试不用于证明真实模型的探索策略已恢复。
